### 6 มาตรการความปลอดภัยก่อนแตะต้องระบบจริง:
1. **การสำรองข้อมูล (Backup First):** ก่อนเริ่มงานแต่ละ Phase ต้อง Dump ฐานข้อมูล MySQL และ Zip ไฟล์โค้ดเก็บไว้ใน `_secure_backups` เสมอ
2. **ห้ามทดสอบบนระบบจริงระหว่างเวลาทำการ:** ห้ามทดสอบแก้ไขไฟล์บน Live NAS ขณะร้านเปิดขายของ การ Deploy ขึ้นระบบจริงจะทำ **นอกเวลาทำการ (เช้าตรู่ก่อนร้านเปิด หรือ ช่วงค่ำหลังปิดร้าน)** เท่านั้น
3. **การทดสอบด้วย 3 บัญชีทดสอบ (Clean Test RBAC):** ทุกฟังก์ชันต้องผ่านการทดสอบด้วย 3 สิทธิ์บทบาท (แอดมิน, พนักงานขาย, ดูคลังสินค้า) ห้ามใช้บัญชีพนักงานจริงทดสอบ
4. **Console F12 สะอาด 100%:** หน้าจอทุกหน้าต้องไม่มีตัวแดง (Runtime Errors) เมื่อกดปุ่มหลักและแถวตาราง
5. **การเปลี่ยนเลขแคช (?v=...):** เปลี่ยนเลขเวอร์ชันแคชของไฟล์ JS/CSS ทุกครั้งที่มีการแก้ เพื่อให้เบราว์เซอร์เครื่องหน้าร้านดึงไฟล์ใหม่อัตโนมัติ โดยพนักงานไม่ต้องคอยเคลียร์แคช
6. **การส่งรายงานยืนยันพร้อมหลักฐาน:** แจ้งรายการไฟล์ที่แก้ไข บรรทัดโค้ด และผลการทดสอบให้ผู้ตรวจสอบ (Analyst) ตรวจซ้ำก่อนเริ่ม Phase ถัดไป

## 1. การวิเคราะห์สถานการณ์และประเด็นสำคัญจากการตรวจจริง (24/10/2026)

### 1.1 ความจริงเรื่อง Chrome Extension (ผลทดสอบจริงรอบ 10:42 และ 10:51 น.)
* **สถานะจริง:** ข้อมูลคำสั่งซื้อสามารถเข้าสู่ระบบได้แล้ว แต่**ข้อมูลที่เข้ามายังมีปัญหาหนัก 8 ประการ** จนไม่สามารถนำไปใช้งานได้จริง:
  1. **การบันทึกซ้ำ (Duplicates):** กดดึงรอบสองเวลา 10:51 น. ระบบดึง 77 แถวเดิมเข้ามาซ้ำ ทำให้ออเดอร์ร้านแต่งระเบิดพุ่งจาก 158 เป็น 237 ชิ้น ➔ *วิธีแก้:* เปลี่ยนคำสั่งบันทึกเป็น `UPSERT` (อ้างอิง `order_sn` + รหัสสินค้า) และลบแถวที่ซ้ำเดิมออกทันที
  2. **การล็อกร้านแต่งระเบิด:** หน้าจอเลือก KingKong ไม่ได้ ➔ *วิธีแก้:* ให้อ่าน `shop_id` จาก Seller Center อัตโนมัติ พร้อมบันทึก `shop_id` กำกับทุกแถว
  3. **Shopee ดึง SKU และราคาไม่ได้:** ขึ้น `NO_SKU` และราคาเป็น `0` ทุกแถว ➔ *วิธีแก้:* แก้ตัวแยกข้อมูล (Parser) ให้อ่าน Seller SKU, ราคาขายจริง, `item_id` และ `model_id` ให้ถูกต้อง
  4. **TikTok อ่านผิดช่อง:** ขึ้น `(ไม่พบ Seller SKU)` และชื่อสินค้า 9 แถวกลายเป็น JSON ดิบ ➔ *วิธีแก้:* ปรับฟังก์ชัน Parse JSON ใน content script ของ TikTok
  5. **Lazada ได้รหัสแพลตฟอร์ม:** ได้ `item_id-sku_id` แทนที่จะได้ Seller SKU ของร้าน ➔ *วิธีแก้:* ชี้เป้าตัวอ่านไปที่ช่อง Seller SKU ในหน้าคำสั่งซื้อ
  6. **เทียบผิดฐานเวลา:** ดึงออเดอร์ค้างหลายวัน (21–24 ต.ค.) แต่นำไปเทียบกับบิลตัดสต๊อกของวันนี้วันเดียว ➔ *วิธีแก้:* เทียบตามเลขออเดอร์ และคัดแยกออเดอร์ "พร้อมส่ง" ออกจาก "พรีออเดอร์"
  7. **สิทธิ์ Host Permissions ใน Extension:** แผนเดิมขอ `https://*/*` ซึ่งกว้างเกินไปและเสี่ยง ➔ *วิธีแก้:* จำกัดเฉพาะโดเมน Seller Center ของ Shopee, Lazada, TikTok และที่อยู่เซิร์ฟเวอร์ร้านเท่านั้น
  8. **ลิงก์ตรงและรูปภาพ (A10, A11):** ดึง `item_id` และ `shop_id` เพื่อสร้างลิงก์ตรงสู่หน้ารายการสินค้าจริงบนแพลตฟอร์ม และดึงภาพ Thumbnail มาเก็บสำรอง

### 1.2 บัคสำคัญในหน้านำสินค้าเข้า (ต้องแก้ก่อนเริ่ม Phase 2)
* **อาการ:** ช่องราคาทุนในหน้านำสินค้าเข้าไม่แสดงให้ใครเห็นเลย แม้ล็อกอินเป็นแอดมิน
* **สาเหตุ:** หน้าเว็บเรียกใช้ `suggestion.cost` แต่ไฟล์ `get_autoprod.php` มีการคอมเมนต์บรรทัดดึง `prod_cost` ทิ้งไว้
* **การแก้ไข:** ปลดคอมเมนต์ใน `get_autoprod.php` พร้อมใส่ตัวเช็คสิทธิ์ Session: ให้ส่งต้นทุนเฉพาะแอดมิน/เจ้าของร้าน ส่วนพนักงานทั่วไปจะไม่ได้รับฟิลด์ต้นทุนนี้เลย

### 1.3 ฟังก์ชันใหม่ที่เจ้าของร้านยืนยัน: "สินค้าเซล" (Sale / Clearance)
* เพิ่มเมนูใหม่ใน Phase 4 รองรับการระบายสินค้า 2 แหล่ง:
  1. สินค้าค้างสต๊อกนาน (เช่น ไม่มีบิลขายเกิน 90 หรือ 180 วัน) โดยติ๊กเลือกจากหน้าสต๊อกเพื่อแยกจำนวนเข้า "สต๊อกเซล"
  2. สินค้าชำรุดเสียหายที่เคลมซัพพลายเออร์ไม่ได้ (ส่งต่อมาจาก Phase 1)
* สต๊อกเซลจะถูกแยกกองชัดเจน ไม่นับรวมในสต๊อกขายปกติ แอดมินเป็นผู้กำหนดราคาเซล (ระบบแสดงต้นทุนและผลขาดทุนให้เห็น) และหน้าขาย POS จะมีแถวสินค้าเซลตัดจากสต๊อกเซลโดยเฉพาะ

## 3. สิ่งที่คงไว้ตามเดิม (เจ้าของร้านตัดสินใจเด็ดขาดแล้ว ไม่ต้องแก้)
1. **ลำดับขั้นตอนในหน้าคิดเงิน:** คงลำดับเดิมไว้คือ `ส่วนลด ➔ รับเงิน ➔ คำนวณเงินทอน` — ไม่ทำระบบคำนวณส่วนลดอัตโนมัติจากยอดรับเงิน เพราะร้านตั้งราคาปลีกไว้สูงและการให้ส่วนลดไม่ได้คิดเป็นเปอร์เซ็นต์คงที่
2. **รูปภาพสินค้า (แสดงผล 570 จาก 12,985 รายการ):** ระบบแสดงภาพทำงานถูกต้องแล้ว รายการที่ไม่มีรูปคือสินค้าที่ทางร้านยังไม่ได้ถ่ายรูปบันทึกเข้าฐานข้อมูล ถือเป็นงานภายในของร้าน ไม่ใช่ข้อผิดพลาดของโปรแกรม

## 4. ประเด็นที่ต้องการคำตอบและการตัดสินใจจากเจ้าของร้าน (3 ข้อ)
1. **กติกาการคัดแยกสินค้าพรีออเดอร์บนแพลตฟอร์ม:** ทางร้านต้องการให้ระบบตัดสินจากสถานะออเดอร์ของแพลตฟอร์ม หรือดูจากจำนวนวันนับถึง "วันที่ต้องจัดส่ง (DTS)" เกินกี่วัน?
2. **รูปแบบรหัสสินค้าใหม่:** นอกจากตัวอักษรภาษาอังกฤษตัวพิมพ์ใหญ่ (A–Z), ตัวเลข (0–9), ขีดกลาง (`-`) และขีดล่าง (`_`) แล้ว ทางร้านต้องการให้อนุญาตเครื่องหมายจุด (`.`) หรือ เครื่องหมายทับ (`/`) ด้วยหรือไม่?
3. **เกณฑ์ระยะเวลาสินค้าค้างสต๊อกสำหรับเสนอเข้า "สินค้าเซล":** ทางร้านต้องการกำหนดสินค้าที่ไม่มียอดขายต่อเนื่องนานกี่วัน (เช่น **90 วัน หรือ 180 วัน**) เพื่อให้ระบบช่วยดึงมาแนะนำให้เจ้าของร้านติ๊กส่งเข้าสต๊อกเซล?
