วิธีแก้: ทุกไฟล์ใน php/ ต้อง include ตัวเช็ค session เดียวกัน (แบบที่ get_user.php ใช้อยู่) ไว้บรรทัดแรก และเช็ค role ซ้ำฝั่งเซิร์ฟเวอร์สำหรับคำสั่งลบ/สำรองข้อมูล
2. ใช้ http ไม่ใช่ https
รหัสผ่านตอนล็อกอินและข้อมูลทั้งหมดวิ่งผ่านอินเทอร์เน็ตแบบไม่เข้ารหัส แนะนำ: ติดตั้ง SSL (เช่น Let’s Encrypt หรือใช้ Cloudflare Tunnel) แล้วบังคับ https
🟠 ระดับสูง — ตัวเลขผิด / เสี่ยงข้อมูลเพี้ยน
3. รายงานสรุปยอดขาย: “ต้นทุนรวม” ไม่สอดคล้องกับยอดขายและกำไร
ตัวอย่างวันที่ 23/10/2026: ยอดขาย ฿53,244 · กำไร ฿20,730 · ต้นทุนรวม ฿49,180 → แต่ ยอดขาย − กำไร = ฿32,514
สาเหตุ: บิล S26-13907 แบบ “ตัดไม่คิดเงิน” (ลูกค้า: ตัดออก) มียอดขาย ฿0 ต้นทุน ฿16,666 แต่กำไรถูกตั้งเป็น 0 แทนที่จะเป็น −16,666 จึงนับต้นทุนเข้ายอดรวม แต่ไม่ได้หักออกจากกำไร และยังถูกนับเป็น 1 บิล ทำให้ค่าเฉลี่ยต่อบิลต่ำกว่าจริง
วิธีแก้ (เลือก 1 แบบ): (ก) ไม่นับบิล “ตัดไม่คิดเงิน” ใน KPI ยอดขาย/ต้นทุน/จำนวนบิล แล้วแยกการ์ด “มูลค่าสินค้าตัดไม่คิดเงิน” ต่างหาก (แนะนำ) หรือ (ข) นับเป็นกำไรติดลบให้สอดคล้องกัน — แก้ใน php/get_sales_summary.php
4. หน้าขาย (POS): กดคิดเงินซ้ำได้ → เสี่ยงบิลซ้ำ/ตัดสต๊อกซ้ำ
ฟังก์ชัน save2db() ถูกเรียกได้ทั้งจากปุ่ม Enter ในช่องรับเงิน และปุ่มคิดเงิน (F8) โดยไม่มีตัวกันระหว่างกำลังส่งข้อมูล ถ้ากด Enter สองครั้งเร็วๆ หรือเน็ตช้าแล้วกดซ้ำ จะส่ง php/save_order.php สองรอบ
วิธีแก้: ตั้งตัวแปร isSaving = true ก่อนส่ง แล้ว return ถ้ายังส่งอยู่ + ปิดปุ่มคิดเงิน ปลดล็อกเมื่อสำเร็จ/ผิดพลาด (ฝั่ง PHP ควรกันซ้ำด้วย token ต่อบิลอีกชั้น)
5. หน้าขาย: บันทึกไม่สำเร็จเพราะเน็ตหลุด → หน้าจอค้าง
การเรียก save_order.php ไม่มี error: callback ถ้าเซิร์ฟเวอร์ล่ม/เน็ตหลุด กล่อง “กำลังโหลด” จะไม่หาย และแท็บพิมพ์บิลที่เปิดไว้ล่วงหน้าค้างเป็นหน้าว่าง พนักงานไม่รู้ว่าบิลบันทึกแล้วหรือยัง → มักกดใหม่ → บิลซ้ำ
เรื่องนี้เป็นปัญหาทั้งระบบ: ทั้งหมด ~127 จุดที่เรียกหลังบ้าน มี ~92 จุดไม่มีการจัดการ error (หน้าขาย 10/10, หน้านำเข้า 10/14, สต๊อก 8/13, จัดการผู้ใช้/ลูกค้า/โกดังทุกจุด)
วิธีแก้: ตั้ง $.ajaxSetup({ error: ... }) กลางไว้ใน navbar.js ให้ซ่อน loading + แจ้ง “เชื่อมต่อไม่ได้ กรุณาเช็คในรายงานบิลก่อนกดใหม่” และปิดแท็บพิมพ์ที่เปิดค้าง
🟡 ระดับกลาง — ฟีเจอร์ไม่ทำงาน / บัคการใช้งาน
6. หน้านำสินค้าเข้า: รายชื่อซัพพลายเออร์+ราคาถูกสุดไม่แสดง
ฟังก์ชัน populateSupplierDatalist() เติมรายการ “ถูกสุด: xx ฿ (สั่งล่าสุด …)” ลงใน #supplier-datalist แต่ในหน้าไม่มี element นี้ และช่องซัพพลายเออร์ไม่มี list=&quot;supplier-datalist&quot; ฟีเจอร์นี้จึงไม่เคยทำงาน
วิธีแก้: เพิ่ม &lt;datalist id=&quot;supplier-datalist&quot;&gt;&lt;/datalist&gt; และใส่ list=&quot;supplier-datalist&quot; ที่ช่องกรอกซัพพลายเออร์
7. หน้าขาย: แก้ไขรายการซ้ำหลายครั้ง → แจ้งเตือนเด้งซ้อน
edit() ผูก event keyup input ใหม่ทุกครั้งที่กดแก้ไข โดยไม่ .off() ของเก่า แก้ไขแถวเดิม 3 ครั้ง = แจ้งเตือน “สินค้ามีจำนวนไม่พอ” เด้ง 3 ชั้น และหลังลบแถว (ระบบเปลี่ยน id แถว) handler เก่ายังอ้างเลขแถวเดิม อาจไปแก้แถวผิด
วิธีแก้: $(&#39;#amount-&#39;+arg).off(&#39;keyup input&#39;).on(...) หรือใช้ event delegation
8. หน้าขาย: กดคิดเงินแล้วไม่มีอะไรเกิดขึ้น
ถ้ายังไม่เลือกลูกค้า หรือช่องรับเงิน/เงินทอนว่าง save2db() จะ return เงียบๆ ไม่มีข้อความบอก
วิธีแก้: แจ้ง “กรุณาเลือกลูกค้า” / “กรุณากรอกจำนวนเงินที่รับ” และโฟกัสไปช่องนั้น
9. หน้าขาย: ไม่ตรวจจำนวน/ราคาติดลบหรือ 0
save() เช็คแค่จำนวนเกินสต๊อก แต่ไม่กันจำนวน 0, ติดลบ, ทศนิยม หรือราคาติดลบ ซึ่งจะทำให้ยอดรวมและสต๊อกเพี้ยน — ควรเช็คทั้งหน้าเว็บและฝั่ง save_order.php
10. ปุ่ม Tab ถูกปิดทั้งหน้า POS
โค้ด keydown บล็อก Tab ทุกที่ (keyCode == 9 → preventDefault) ทำให้ใช้คีย์บอร์ดเลื่อนช่องในหน้าต่างอื่น (เช่น popup เลือกสินค้า) ไม่ได้ ควรบล็อกเฉพาะช่องที่ใช้ Enter นำทาง
🟢 ประสิทธิภาพและความเรียบร้อยของโค้ด
get_autoprod.php ส่งสินค้าทั้งหมด 2.7 MB ทุกครั้งที่เปิดหน้าขาย/นำเข้า/โอนย้าย — ในร้านเร็ว (~0.3 วิ) แต่ผ่านมือถือ/4G จะช้า แนะนำค้นหาแบบพิมพ์แล้วค่อยดึง (ส่ง keyword ไป server) หรือ cache + gzip
ใช้ async: false (โหลดแบบค้างหน้าจอ) ~21 จุด หน้าขายมี 7 จุด (search_amount, search_cusprice, search_img, get_sale) ทำให้หน้าจอค้างระหว่างสแกนบาร์โค้ด ควรเปลี่ยนเป็น async
โค้ดค้าง (dead code): หน้าขายสร้างเมนู #c / เรียก setwareto() ที่ไม่มีอยู่จริง; หน้าสต๊อกอ้าง #edit-bundle-action-wrap ที่ไม่มี — ลบทิ้งได้
id ซ้ำ: หน้าขายมี id=&quot;head&quot; 2 ตัว, รายงานบิลมี printModal และ reModal ซ้ำ 2 ตัว — อาจเปิด modal ผิดตัว
ต่อ HTML ด้วยชื่อสินค้าตรงๆ (เช่น &#39;&lt;td&gt;&#39;+name+&#39;&lt;/td&gt;&#39;) ถ้าชื่อสินค้า/ลูกค้ามีเครื่องหมาย ’ หรือ &lt; จะทำให้ตารางพัง และเป็นช่อง XSS ควร escape ก่อนแสดง
เมนูด้านบนตัวหนังสือแตก 2-3 บรรทัด บนจอ ~1300px (เมนูเยอะ) แนะนำย่อชื่อหรือรวมเป็น dropdown
